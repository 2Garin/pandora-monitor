# Pandora NAV-08 Move → Uptime Kuma

Небольшой монитор для маяка Pandora NAV-08 Move: раз в 30 минут запрашивает состояние устройства через Pandora Online, сохраняет историю напряжения батареи в SQLite и отправляет три статуса в Uptime Kuma. Работает в Docker, в том числе на Synology NAS с Container Manager. Входящие порты не нужны.

## Что показывают три монитора

В Uptime Kuma создайте **три отдельных монитора типа Push** с **Heartbeat Interval = 3600 секунд** (60 минут):

| Монитор | Когда `up` | Когда `down` |
| --- | --- | --- |
| Связь с маяком | Последний контакт менее 48 часов назад | Контакт старше порога |
| Батарея | Есть свежее значение не ниже 4,0 В | Значение ниже порога, отсутствует или устарело |
| Работа опроса | Удалось опросить Pandora, сохранить показание (если оно есть) и отправить статусы в Kuma | Ошибка опроса, записи или отправки |

При остановке контейнера push-запросы прекратятся, и Kuma отметит мониторы как недоступные после истечения своего интервала. Порог возраста и напряжения можно настроить в `.env`; 4,0 В — только значение по умолчанию, выбирайте его с учётом используемых батарей. Опрос каждые 1800 секунд даёт две попытки отправить статус за интервал Kuma.

## Установка на Synology NAS

Нужны Docker / **Container Manager**, доступ NAS к Pandora Online и Uptime Kuma, а также SSH-доступ для подготовки каталога данных. Команды ниже выполняются **в папке проекта** на NAS, где лежит `compose.yaml`.

1. Скопируйте файлы проекта на NAS. Если `.env` ещё нет, создайте его из шаблона и заполните своими данными. При обновлении проекта **не перезаписывайте существующий `.env`**:

   ```sh
   cp .env.example .env
   ```

   `PANDORA_LOGIN` и `PANDORA_PASSWORD` — учётные данные Pandora Online; `PANDORA_DEVICE_ID` — числовой ID маяка в этой учётной записи. `KUMA_URL` — адрес вашего Uptime Kuma (например, `https://uptime.example.com`, без `/api/push/...`). Для каждого из трёх Push-мониторов скопируйте **свой** токен из URL push-ссылки Kuma: часть между `/api/push/` и `?`. Впишите их в `KUMA_PUSH_CONNECTION`, `KUMA_PUSH_BATTERY` и `KUMA_PUSH_API` соответственно. Сами токены и пароль не публикуйте.

2. Папка `data/` сохраняется в Git благодаря `.gitkeep` и будет создана при клонировании проекта. Дайте контейнеру права на неё. Приложение в контейнере запускается с UID/GID **65534:65534**; на Synology эти числа могут отображаться под другим именем пользователя. Если вы перенесли файлы способом, который не сохранил пустую папку, `mkdir -p` создаст её; существующие данные команда не удаляет:

   ```sh
   mkdir -p data
   sudo chown -R 65534:65534 data
   sudo chmod 700 data
   ```

   **Создавать `data/pandora.sqlite3` вручную не нужно:** Python создаст файл и таблицу `battery_history` при первом полученном показании напряжения. `.gitkeep` не выдаёт контейнеру права на запись, поэтому шаг с `chown` всё равно необходим. Если после него запись по-прежнему не работает, проверьте права самого файла БД и доступность тома NAS для записи.

3. Запустите проект через SSH или импортируйте `compose.yaml` как проект в Container Manager (при использовании UI папку `data/` и `.env` подготовьте заранее в каталоге проекта):

   ```sh
   docker compose up -d --build
   docker compose logs -f pandora-monitor
   ```

   Первый опрос выполняется сразу, далее — с интервалом `POLL_INTERVAL_SECONDS`. Для просмотра последних 30 записей истории (время МСК):

   ```sh
   ./history.sh
   ```

   До первого показания файл базы ещё не появится, поэтому историю смотреть рано. Если `history.sh` не запускается из-за прав файла на NAS, используйте `sh history.sh`.

## Настройки

Все настройки задаются в `.env`; шаблон — `.env.example`. Необязательные параметры (значения по умолчанию):

| Параметр | Значение | Назначение |
| --- | --- | --- |
| `POLL_INTERVAL_SECONDS` | `1800` | Период опроса, минимум 300 секунд |
| `MAX_OFFLINE_HOURS` | `48` | Порог давности последнего контакта, часы |
| `MIN_BATTERY_VOLTAGE` | `4.0` | Нижний порог напряжения, В |
| `SQLITE_PATH` | `/data/pandora.sqlite3` | Путь к БД внутри контейнера; при смене пути проверьте том и `history.sh` |

Том `./data:/data` хранит базу на NAS независимо от пересоздания контейнера. Запись в `battery_history` производится только при новом времени последнего контакта маяка: повторные опросы не дублируют показания. Для резервной копии сохраните каталог `data/` (при копировании работающей SQLite-базы используйте корректный механизм резервного копирования SQLite или остановите контейнер).

Файл `.env` и содержимое `data/`, кроме `.gitkeep`, исключены из Git; данные и `.env` исключены из сборочного контекста Docker. Перед публикацией репозитория убедитесь, что пароли и реальная база не были добавлены в историю Git ранее.
